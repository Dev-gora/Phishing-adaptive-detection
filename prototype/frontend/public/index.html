What this build actually does

  • Real models, real data. Random Forest, XGBoost, KNN and LightGBM are fitted on the 11,430-row benchmark, split 60/20/20.
  • Dataset metrics only on the held-out split. The test partition is never used for feature selection or tuning.
  • Single-URL predictions are not accuracy. A URL receives a class and a probability; accuracy is only reported for a labelled evaluation set.
  • No invented external data. Domain age, WHOIS, DNS, search index and page rank are not retrieved, so they are never shown.

Research Methodology

How the models behind this interface were produced, and the limits that follow from those choices.

Pipeline

  1. Load. The published benchmark is read unchanged from data/dataset_phishing_raw.csv (11,430 rows, URL + 87 features + label).
  2. Clean. Ambiguous duplicate URLs are dropped, exact duplicate feature rows are removed, six zero-variance columns are dropped, and the label is encoded (phishing = 1).
  3. Split. Stratified 60 / 20 / 20 into train, validation and test. The test split is touched only for the numbers shown in Model Playground.
  4. Select. Each method ranks features using the training split only. SHAP and LIME use a shared Random Forest surrogate; permutation and RFE are out-of-sample aware.
  5. Fit & evaluate. The chosen subset is used to fit each model; accuracy, precision, recall, F1 and ROC-AUC are computed on the 2,252 test rows.
  6. Explain. Tree SHAP for tree ensembles, LIME for any model, both on the same extracted feature vector the prediction used.

Metric definitions

Accuracy
Correct predictions / all predictions. Misleading under class imbalance, so it is never the sole ranking criterion.
Precision
Of URLs flagged suspicious, the share that really are phishing.
Recall
Of the phishing URLs, the share that were caught.
F1
Harmonic mean of precision and recall; the primary comparison metric here.
ROC-AUC
Ranking quality of the predicted probability, threshold-independent.
Prediction time
Mean milliseconds per sample to score the test split, excluding training.

Limitations

  • The live analyser can only compute URL-derived features. Page-content and third-party features are excluded rather than guessed, which is why live models use 32 of the 81 modelled columns.
  • Dataset metrics are therefore not directly comparable with the full-feature results in the paper.
  • A single-URL prediction has no ground truth, so no accuracy is reported for it.
  • SHAP values explain the model, not the website.

Feature-selection cost in this build

Measured once on the 32-feature URL space and cached; the rankings are reused by every playground run.
